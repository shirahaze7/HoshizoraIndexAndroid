# 星空指数チェッカー (Android)

登録した複数の地点の星空指数（時間別の星の見えやすさ）をアプリ上で手軽に確認・管理し、指定した条件（しきい値や対象時間帯）を満たす日に自動で通知を受け取ることもできるAndroidアプリです。

Kotlin + Jetpack Compose + Room + WorkManager + Retrofit + Moshi で構成されています。

## 主な機能

- **監視地点の登録・管理**
  - アプリ内で監視したい地点（地点名・緯度・経度・標高）を追加・編集・削除できます。
  - 各地点のカード上で、取得済みの時間別星空指数（18時〜翌8時）や取得日時を一覧確認できます。
- **JSON形式での地点データのバックアップ・共有 (インポート / エクスポート)**
  - 登録した地点リストをJSONファイルとして保存・共有したり、保存したJSONファイルから一括で登録できます。
- **バックグラウンド自動チェック & 通知**
  - WorkManagerを利用し、毎日指定した時間に自動でAPIを取得・判定し、条件に合う地点があれば端末に通知します。
  - 端末再起動後もスケジュールが自動再登録されます。
- **詳細な設定カスタマイズ**
  - **通知しきい値**: 星空指数の判定基準（0〜4）を変更可能。
  - **対象時間帯**: 判定対象とする時間帯（18時〜翌8時の任意の時間）を個別選択可能。
  - **実行時刻**: 毎日の自動チェック時刻（時・分）を設定可能。
  - **空通知の切り替え**: 条件を満たす地点がない日にも通知を出すかどうかを設定可能。
  - **今すぐ実行**: テスト用に手動で即座にチェックを実行可能。

## 使い方

### 基本操作
1. アプリ起動後、右下の「＋」ボタンから監視地点を追加します。
   - 緯度経度は、地図アプリ（Googleマップ等）で調べた値（例: 35.658581, 139.745433）を入力してください。
2. 右上の歯車アイコン（設定）をタップし、通知させたい星空指数のしきい値や、毎日のチェック時刻を調整します。
3. 手動で星空指数を取得・テストしたい場合は、右上の再生アイコン（▶）をタップしてください。

## JSONインポート・エクスポートの使い方

複数端末でのデータ共有や、機種変更時のデータ移行、バックアップ用に、地点データをJSONファイルとして出力（エクスポート）したり、読み込み（インポート）することができます。

### 1. エクスポート（地点データの出力・保存）
1. ホーム画面右下の「アップロードアイコン（Icon: Upload）」（一番左の小さな丸ボタン）をタップします。
2. Androidの共有ダイアログが起動します。
3. Google ドライブやファイル保存アプリ、メール、メッセージアプリなどを選び、`hoshizora_locations.json` を保存または送信します。

### 2. インポート（地点データの読み込み）
1. ホーム画面右下の「ダウンロードアイコン（Icon: Download）」（中央の小さな丸ボタン）をタップします。
2. ファイル選択画面が開くので、バックアップしてあった `.json` ファイルを選択します。
3. 読み込みが成功すると「インポートしました」と表示され、ファイルに記述された地点が一括登録されます。

### 手動でJSONファイルを作成して読み込ませる場合
PCやテキストエディタで以下のようなフォーマットのJSONファイルを作成してインポートすることも可能です。

```json
[
  {
    "name": "東京タワー",
    "lat": 35.658581,
    "lon": 139.745433,
    "alt": 0.0
  },
  {
    "name": "富士山頂",
    "lat": 35.360625,
    "lon": 138.727363,
    "alt": 3776.0
  }
]
```

- `name`: 地点名 (文字列)
- `lat`: 緯度 (数値)
- `lon`: 経度 (数値)
- `alt`: 標高 (数値、省略時は0.0)

※インポート時、すでに登録されている地点と重複していても上書きされず、新しい地点として追加されます。

## 緯度・経度・標高の仕様と推奨精度

APIリクエスト時における緯度 (`lat`)・経度 (`lon`)・標高 (`alt`) の仕様および実測テスト結果です。

### 1. 実測テスト結果
- **桁数の許容範囲**: 小数なし（整数）から小数第15位以上まで、エラーになることなく正常に受け付けます。
- **レスポンス変化の境界**: 内部的に約10km四方の気象区画（メッシュ）単位で計算されているため、およそ **7〜10km 以上（緯度・経度の差で約 0.07度 以上）** 離れた場合のみ星空指数が変化します。数メートル〜数百メートル単位の微小な差（小数第3位以下）では同じ区画と判定され、返ってくる指数は完全同一になります。

### 2. 推奨入力精度
- **緯度・経度 (`lat` / `lon`)**: **小数第2位〜第6位**
  - Googleマップ等からコピーした標準的な桁数（例: `35.658581, 139.745433`）をそのまま入力して問題ありません。気象区画の最高精度を完全にカバーできます。
- **標高 (`alt`)**: **整数（メートル単位）**
  - 例: `0` や `3776`（富士山）。必要に応じて小数第1位までの入力で十分です。

## 注意点・補足

- **Web APIの使用について**
  - 外部の星空指数データ取得APIを利用しているため、サービス側の仕様変更等により動作しなくなる可能性があります。
- **実行時刻の精度について**
  - Android 12以降の省電力機能（Dozeモード等）やアラーム制限の影響により、WorkManagerの実行タイミングが数分〜数十分前後する場合があります。
- **利用頻度について**
  - サーバーへの負荷を考慮し、頻繁な連続アクセスは避け、1日1〜数回程度の利用にとどめてください。

```
├── .github/

│   └── src/main/

│       └── java/com/hoshizora/notifier/
│           ├── HoshizoraApplication.kt   # アプリ起動時の初期化
│           ├── MainActivity.kt           # ナビゲーション構成
│           ├── data/                     # Room DB (地点・結果) & SharedPreferences (設定)
│           ├── network/                  # Retrofit + Moshi (星空指数APIモデル)
│           ├── notification/             # 通知表示ヘルパー
│           ├── ui/                       # Jetpack Compose UI (地点一覧, 追加・編集, 設定)
│           └── worker/                   # WorkManager (バックグラウンド自動チェック)
```
